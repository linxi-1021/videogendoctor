你的 Fig.2 判断是对的，但我会再往前推一步：**VideoGenDoctor 的图组不要按“benchmark 论文”来画，而要按“diagnosis + evidence + repair benchmark”来画**。VBench、FETV、EvalCrafter、T2V-CompBench 这类论文主要证明“我能评估”；你这篇更应该证明“我能定位、解释、修复，并量化闭环收益”。

**参考论文给出的图形规律**

我看了几类相近工作：

- **VBench**：强调 hierarchical / disentangled dimensions、prompt suite、evaluation methods、human preference annotations，用图建立“完整评价体系”的可信度。来源：[VBench arXiv](https://arxiv.org/abs/2311.17982)。
- **EvalCrafter**：强调 700 prompts、17 objective metrics，并用 human alignment 得到 leaderboard，适合参考“多指标如何汇总成模型诊断”。来源：[EvalCrafter arXiv](https://arxiv.org/abs/2310.11440)。
- **FETV**：重点是 fine-grained、multi-aspect、temporal-aware prompt categorization，并检查自动指标与人类评价相关性。来源：[FETV NeurIPS](https://proceedings.neurips.cc/paper_files/paper/2023/hash/c481049f7410f38e788f67c171c64ad5-Abstract-Datasets_and_Benchmarks.html)。
- **T2V-CompBench**：把 compositionality 拆成 consistent/dynamic attributes、spatial、motion/action binding、object interaction、numeracy，并结合 MLLM / detection / tracking metrics。来源：[T2V-CompBench arXiv](https://arxiv.org/abs/2407.14505)。
- **VideoPhy / VideoPhy-2**：证明某一类失败不是泛泛质量问题，而是“物理规则失效”，适合参考细粒度 failure evidence 和 rule-level analysis。来源：[VideoPhy arXiv](https://arxiv.org/abs/2406.03520)。
- **GenAI-Bench / VideoScore / AIGCBench**：强调 human alignment、candidate ranking、multi-dimension score 与自动指标可信性。来源：[GenAI-Bench arXiv](https://arxiv.org/abs/2406.13743)、[AIGCBench](https://www.sciencedirect.com/science/article/pii/S2772485924000048)、[VideoScore](https://huggingface.co/papers/2406.15252)。

3. **Fig.3：Closed-loop Repair Curve**
   
   这张非常关键，建议放主文，不要放 appendix。
   
   画法：
   
   - x-axis：repair iteration，`0 / 1 / 2 / 3`
   - y-axis 左轴：failure rate 或 unresolved failure count
   - y-axis 右轴：quality / preference / success rate
   - 多条线：All、Identity、Motion、Alignment，或者不同模型
   - 加阴影：95% CI / bootstrap interval
   
   这张图回答：**修复是不是有效，是否越修越好**。  
   这比只报告 before/after table 更像顶会主图。

4. **Fig.4：Qualitative Evidence + Patch Example**
   
   这是你文章最能打动人的图。建议每个 case 用 4 列：
   
   ```text
   Prompt | Failure Evidence | Patch Code | Repaired Result
   ```
   
   每个视频案例放 3-4 个 keyframes，而不是单帧。  
   每个 evidence span 上方标注：
   
   ```text
   t=2.4s-3.8s, ID_FACE_DRIFT, confidence=0.87
   ```
   
   Patch 部分不要写自然语言，写像代码块一样的 patch：
   
   ```yaml
   code: ID_FACE_DRIFT
   evidence: [2.4s, 3.8s]
   patch:
     inject_reference_frame: frame_000
     identity_lock: high
   ```
   
   这张图回答：**失败是怎么被发现、怎么被修的**。  
   它应该是最“VideoGenDoctor”的图。

5. **Fig.5：Per-category Diagnosis / Repair Performance**
   
   参考 VBench Fig.2 和 T2V-CompBench 的 multidimensional result，但别画成普通柱状图。建议：
   
   - 雷达图或 grouped bar：`ID / CA / MO / AL / ST / SC`
   - 每类显示：
     - detection F1
     - temporal IoU
     - patch success rate
   - 模型维度可以用颜色或小 multiples：
     - Runway / Pika / ModelScope / AnimateDiff / Sora-like samples
   
   更推荐 **small multiples grouped bar**，少用雷达图。雷达图视觉漂亮但数值难读。  
   这张图回答：**系统在哪些失败类型上强，哪些还弱**。

6. **Fig.6：Human / Judge Agreement**
   
   如果篇幅够，这张可选但很有用。
   
   画法：
   
   - x-axis：human preference
   - y-axis：VideoGenDoctor score 或 repair success score
   - 每个点是一个 sample pair
   - 右侧放 Kendall / Spearman correlation
   - 或画 confusion matrix：human says repaired vs system says repaired
   
   这张图回答：**自动诊断/修复是不是和人类感受一致**。  
   这是 VBench、FETV、EvalCrafter、GenAI-Bench 都在强调的可信性维度。
